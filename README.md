# VC Warehouse Simulation

Общая библиотека компонентов и расчётных моделей Visual Components для команды и её ИИ-агентов.

**Статус:** подготовлена инфраструктура проекта. Рабочие модели и компоненты ещё не добавлены; производительность и точность не подтверждены.

## Быстрый старт

В Git Bash:

```bash
git lfs install
git clone https://github.com/phantomhaif/vc-warehouse-simulation.git
cd vc-warehouse-simulation
git lfs pull
python tools/validate_catalog.py
```

Репозиторий публичный: читать и клонировать его можно без приглашения. Для прямой отправки изменений нужен доступ collaborator; также можно предложить изменения через fork и Pull Request. На Windows вместо `python` может использоваться `py -3`.

## Содержание

| Каталог | Назначение |
| --- | --- |
| `components/` | Пакеты компонентов: модель, исходники, интерфейсы, зависимости, тесты |
| `layouts/` | Сборочные планировки ASRS-B, ASRS-P 3DS, сортировки |
| `scenarios/` | Параметры воспроизводимых экспериментов |
| `results/` | Отчёты о прогонах и проверках |
| `docs/` | Требования, архитектура, порядок совместной работы |
| `templates/component/` | Шаблон нового компонента |
| `tools/` | Проверки каталога без установленного VC |

Начните с [разбора проекта](docs/project-brief.md), [плана реализации](docs/implementation-plan.md) и [порядка работы](CONTRIBUTING.md). ИИ-агент должен первым прочитать [AGENTS.md](AGENTS.md).

Большие двоичные модели хранятся через Git LFS. Скрипты экспортируются отдельными текстовыми файлами для ревью. GitHub проверяет структуру каталога; физику, API и симуляцию проверяем на рабочем месте с лицензированной целевой версией VC.

Репозиторий публичный. Не добавляйте конфиденциальные материалы заказчика. Права на сторонние библиотечные модели сохраняются за их владельцами; добавляйте только материалы, которые команда вправе публиковать.
